# منصّة مطابقة فواتير الاتصالات

وزارة التربية والتعليم — مملكة البحرين
إدارة المنشآت التعليمية · قسم الهندسة والصيانة · **مجموعة الهندسة الإلكترونية**

منصّة داخلية تطابق فواتير الاتصالات الشهرية بأمر الشراء وسجله المعتمد، وتُصدر
تقريراً رسمياً يُحال إلى المزوّد لتأكيده قبل تمرير الفواتير للدفع.

> خطوات الرفع في **[DEPLOY.md](./DEPLOY.md)** — كلها من المتصفح، بلا طرفية.

---

## ماذا تفعل

ترفع ملفات فواتير الشهر كما تنزل من بوابة المزوّد (ملف `xlsx` لكل حساب). المنصّة
تقرأها **داخل متصفحك**، تطابقها بمصدرين، وتُخرج النتيجة مرتّبة من الأخطر:

| المخرج | لماذا يهم |
|---|---|
| حسابات في السجل ولم تصل فاتورتها | يمنع نسيان دفع فاتورة حساب |
| حسابات إضافية خارج السجل المعتمد | تحتاج مبرراً قبل الصرف |
| أرقام / خطوط إضافية ظهرت | كل خط بمبلغه |
| خطوط اختفت من الفوترة | إلغاء أم فاتورة لم تصل |
| **مبالغ محوّلة من شهور سابقة** | `Total Billed` − `Current Charges` لكل حساب |
| تغيّر المبلغ لكل حساب | مقابل الشهر السابق أو السجل، بالنسبة |
| خطوط ضريبتها لا تساوي النسبة المعتمدة | لكل خط |
| اتجاه الإنفاق الشهري | بعد حفظ شهرين |
| **تقرير PDF رسمي** | بترويسة الوزارة وختم المجموعة وخانات التأكيد |

## أوامر الشراء

كل أمر شراء له فترته ونسبة ضريبته وتدفقه المالي وسقفه وسجل حساباته وخطوطه،
والشهور المحفوظة مرتبطة بأمرها. المنصّة تعرض لكل أمر **كم مُرِّر منه وكم تبقّى**،
شاملاً الفواتير التي مُرِّرت قبل المنصّة (من جدول تسليم الفواتير).

المسؤول يضيف أوامر مستقبلية ويعدّلها يدوياً، ويستورد التدفق المالي من ملف إكسل.

## الأدوار

| الدور | يستطيع |
|---|---|
| **مراجع** | رفع الفواتير، المطابقة، إصدار التقرير، حفظ الشهر وتغيير حالة تمريره |
| **مسؤول** | كل ما سبق + إدارة الحسابات + إضافة أوامر الشراء وتعديلها وحذفها |

الدخول بالرقم الشخصي للموظف. كلمة السر الأولية `Moe@` + الرقم الشخصي،
**والمنصّة تُلزم بتغييرها عند أول دخول**.

## البنية

```
main.ts                    الخادم: API + Deno KV + الجلسات + خدمة الواجهة
deno.json                  مهام التشغيل والفحص
static/app.html            الواجهة كاملة (صفحة واحدة، بلا حزم ولا بناء)
seed/staff.json            الحسابات الأولية (بلا كلمات سر — تُشتق عند البذر)
seed/purchase-orders.json  أوامر الشراء وسجلاتها والفواتير المُرِّرة سابقاً
```

### واجهة الـ API

| المسار | الطريقة | الصلاحية |
|---|---|---|
| `/api/login` · `/api/logout` · `/api/me` | POST · POST · GET | — |
| `/api/state` | GET | جلسة |
| `/api/password` | POST | جلسة |
| `/api/users` · `/api/users/:id` · `/api/users/:id/password` | POST · PATCH/DELETE · POST | مسؤول |
| `/api/po/:id` · `/api/active-po` | PUT/DELETE · PUT | مسؤول |
| `/api/months/:po/:month` | PUT · PATCH · DELETE | جلسة |

كل طلب مغيِّر يتطلب ترويسة `X-Requested-With: batelco-platform` — يمنع تنفيذه
من موقع آخر.

## الأمن

- كلمات السر تُشتق بـ PBKDF2-SHA256 (١٢٠ ألف دورة) بملح لكل حساب، **ولا تُعاد
  إلى المتصفح إطلاقاً**.
- التحقق يقارن مقارنة ثابتة الزمن، ويشتق حتى للحسابات غير الموجودة كي لا يكشف
  زمن الرد وجود الحساب.
- الجلسات في كوكي `HttpOnly` + `Secure` + `SameSite=Lax`، وتنتهي بعد ١٢ ساعة.
- ٨ محاولات دخول فاشلة لكل رقم في ١٥ دقيقة، ثم حظر مؤقت.
- تغيير رقم شخصي أو حذف حساب يُبطل جلساته القائمة فوراً.
- **ملفات الفواتير لا تُرفع للخادم** — تُقرأ في المتصفح، ويُحفظ ناتج المطابقة فقط.

## المنطق الحرج (لا يُغيَّر بلا سبب)

- المبلغ يُقرأ من `Current Charges Excluding VAT` حصراً — `Total Billed` يشمل
  الرصيد السابق، و`Current Charges` شامل الضريبة.
- ترتيب مطابقة العناوين: `excl` قبل `incl` قبل `billed`.
- مفتاح مطابقة الخط = **(رقم الحساب + Bill Profile)**.
- أساس المقارنة يستبعد الشهر الجاري نفسه.
- الاستهلاك يُحسب **قبل الضريبة** — لأن جدول تسليم الفواتير يقيّد المبالغ بدون ضريبة.
